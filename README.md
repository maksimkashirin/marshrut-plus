# Маршрут+

**Маршрут+** — чат-бот и мини-приложение в MAX для родителей, которые уже получили заключение ПМПК и решили воспользоваться содержащимися в нём рекомендациями.

MVP помогает родителю пройти организационный путь после ПМПК: понять, что делать дальше, какие действия уже выполнены, какой шаг следующий и на каком официальном источнике основан маршрут.

Пилотная территория MVP — **Хабаровский край**.

---

## 1. Назначение решения

После получения заключения ПМПК родителю необходимо самостоятельно разобраться:

- куда передать заключение;
- какие документы подготовить;
- какие заявления подать;
- как подтвердить регистрацию документов;
- как узнать, каким образом образовательная организация реализует рекомендации;
- что делать следующим шагом.

Информация может быть распределена между официальными источниками и организациями.

Маршрут+ собирает этот путь в единый последовательный маршрут внутри MAX.

Продукт не заменяет ПМПК, образовательную организацию или государственные информационные системы и не принимает юридически значимых решений.

---

## 2. Целевая аудитория

Приоритетный пользователь:

> родитель ребёнка, который уже получил заключение ПМПК и решил воспользоваться рекомендациями ПМПК.

В текущем MVP поддерживается сценарий для Хабаровского края.

---

## 3. Основной пользовательский сценарий

1. Пользователь открывает чат-бот Маршрут+ в MAX.
2. Переходит в подключённое мини-приложение.
3. Подтверждает, что заключение ПМПК уже получено.
4. Выбирает рекомендации из тестового набора.
5. Система создаёт персональный маршрут.
6. Пользователь видит:
   - общий прогресс;
   - количество выполненных шагов;
   - следующий шаг;
   - описание действия;
   - официальный источник;
   - полный список шагов.
7. После выполнения действия пользователь отмечает шаг как завершённый.
8. Прогресс и следующий шаг пересчитываются автоматически.

Результат сценария:

> пользователь понимает своё текущее состояние, выполненные действия и следующий организационный шаг по реализации рекомендаций ПМПК.

---

## 4. Границы MVP

Маршрут+ **не выполняет**:

- диагностику ребёнка;
- определение ОВЗ;
- интерпретацию медицинских данных;
- изменение рекомендаций ПМПК;
- профессиональную разработку индивидуального образовательного маршрута;
- запись на ПМПК;
- автоматическую передачу документов в государственные системы;
- юридическую оценку действий образовательной организации.

В MVP используются только тестовые и синтетические данные.

Реальные персональные, медицинские данные и реальные заключения детей не используются.

---

## 5. Архитектура

```text
                         MAX
                          |
                          | HTTPS
                          v
                   +-------------+
                   |    Caddy    |
                   |  80 / 443   |
                   +------+------+
                          |
             +------------+-------------+
             |                          |
             v                          v
      React mini-app                /api/*
                                      |
                                      v
                                  FastAPI
                                      |
                                      v
                                 PostgreSQL

MAX API <---------------------- MAX bot worker
                                  long polling
```

Компоненты:

- **React + TypeScript + Vite** — интерфейс мини-приложения;
- **Caddy** — web server, reverse proxy и HTTPS;
- **FastAPI** — REST API и бизнес-логика;
- **PostgreSQL 16** — хранение пользователей, кейсов, маршрутов и источников;
- **SQLAlchemy** — ORM;
- **Alembic** — миграции базы данных;
- **MAX Bot API** — взаимодействие с чат-ботом;
- **Docker Compose** — воспроизводимый запуск всего решения.

---

## 6. Компоненты Docker Compose

`docker compose` запускает четыре сервиса:

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL |
| `backend` | FastAPI, миграции Alembic и seed тестовых рекомендаций |
| `bot` | MAX-бот в режиме long polling |
| `frontend` | production-сборка React + Caddy |

Все локальные компоненты решения запускаются одной командой.

---

## 7. Требования

Для локального запуска необходимы:

- Docker;
- Docker Compose;
- доступ в интернет для обращения к MAX API;
- токен чат-бота MAX для проверки функций бота.

Отдельная установка Python, PostgreSQL или Node.js для Docker-запуска не требуется.

## 8. Переменные окружения

Создайте `.env` на основе `.env.example`.

Пример:

```env

POSTGRES_PASSWORD=change_me

MAX_BOT_TOKEN=
MAX_API_URL=https://platform-api2.max.ru

MINI_APP_URL=

```

### Переменные

| Переменная | Назначение |
|---|---|
| `POSTGRES_DB` | имя базы PostgreSQL |
| `POSTGRES_USER` | пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | пароль PostgreSQL |
| `DATABASE_URL` | строка подключения FastAPI к PostgreSQL |
| `MAX_BOT_TOKEN` | токен чат-бота MAX |
| `MAX_API_URL` | базовый URL API MAX |
| `MINI_APP_URL` | публичный HTTPS URL mini-app |
| `SITE_ADDRESS` | адрес, который обслуживает Caddy |

Рабочие токены, пароли и ключи **не размещаются в репозитории**.

## 9. Локальный запуск

Из корня проекта:

```bash
docker compose up -d --build
```

Команда:

1. запускает PostgreSQL;
2. ожидает готовности базы;
3. применяет миграции Alembic;
4. добавляет/обновляет тестовый набор рекомендаций;
5. запускает FastAPI;
6. запускает MAX bot worker;
7. собирает React mini-app;
8. запускает Caddy.

Проверка состояния:

```bash
docker compose ps
```

Ожидаются четыре работающих контейнера:

```text
marshrut_plus_db
marshrut_plus_backend
marshrut_plus_bot
marshrut_plus_frontend
```

У PostgreSQL должен быть статус `healthy`.

## 14. Пошаговая техническая проверка API

### Проверка доступности

```bash
curl http://localhost/api/health/db
```

Ожидаемый ответ:

```json
{
  "status": "ok",
  "database": "connected"
}
```

### Получение рекомендаций

```bash
curl http://localhost/api/recommendations
```

Ожидается JSON-массив рекомендаций.

### Основной API-сценарий

1. `POST /users` — создать тестового пользователя.
2. `POST /cases` — создать кейс для региона `Хабаровский край`.
3. `GET /cases/{case_id}/overview` — получить рекомендации, маршрут и dashboard.
4. Получить `dashboard.next_step.id`.
5. `PATCH /steps/{step_id}` со статусом `completed`.
6. Повторно получить overview/dashboard.
7. Убедиться, что прогресс изменился и следующий шаг пересчитан.

Подробное описание автоматизируемых проверок находится в:

```text
DATA-API.yaml
```

## 15. Ожидаемое поведение системы

После создания кейса система:

- создаёт последовательность базовых шагов;
- добавляет шаги, связанные с выбранными рекомендациями;
- сохраняет маршрут в PostgreSQL;
- рассчитывает количество выполненных шагов;
- рассчитывает процент прогресса;
- определяет следующий незавершённый шаг;
- предоставляет официальный источник для шага, если он задан.

После перевода шага в `completed`:

- сохраняется новое состояние;
- обновляется дата выполнения;
- пересчитывается dashboard;
- следующим становится следующий незавершённый шаг.

## 23. As Is → To Be

### As Is

После получения заключения ПМПК родитель самостоятельно:

- ищет информацию в разных источниках;
- определяет последовательность действий;
- отслеживает выполненные шаги;
- возвращается к документам и сайтам;
- пытается понять, что делать дальше.

### To Be

Маршрут+:

- формирует единый маршрут;
- показывает только следующий актуальный шаг;
- сохраняет прогресс;
- связывает действия с официальными источниками;
- позволяет вернуться к маршруту внутри MAX.

---

## 24. Ожидаемый эффект

После пилотного запуска предполагается оценивать:

- время, необходимое пользователю для определения следующего шага;
- долю пользователей, прошедших маршрут до заявленного результата;
- количество ручных поисков информации;
- количество возвратов к маршруту;
- завершение отдельных шагов маршрута.

На этапе MVP эти показатели являются проверяемыми продуктовыми гипотезами.
